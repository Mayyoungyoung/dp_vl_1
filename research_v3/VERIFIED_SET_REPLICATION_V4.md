# Replication and closure decision

Registered after full-population gate/budget_match/set_point seed0 and before
set_project seed0 evaluation. Same additional7200 command-second ledger.

Full-population set_point seed0 reaches valid.917969, distinct7.343750 and known
recall.724840. It does not clear the primary distinct+.3 gate against simple gate
(7.361111). Cost-only budget_match reaches.888021/6.756944/.775959. Thus no new
mechanism is currently accepted. Do not lower the primary gate or replace it with
known recall after seeing this tradeoff.

Replicate gate, budget_match and set_point with paired continuation seeds1/2 to
determine whether the simplest useful change and the coverage/recall tradeoff are
stable. Also run ordinary seeds1/2 as the same-update control. Repeat set_project
only if its seed0 clears the registered gate versus gate and set_point; otherwise
stop region-model trials. These are a shared historical initializer and fixed
DEV families, not three independently pretrained VLMs or a held-out final test.

Run ordinary replay of set_point's actual acquired positives on seed0 as an
equal-information check. This is a diagnostic even if the primary gate fails:
it can reject a claimed need for the online assignment. No tuning of replay to
favor either method. Existing same-input hashes and complete fixed q apply.

Secondary analysis uses the already-sealed DEV pools and the frozen historical
parent edit witnesses (2169 surviving-mode opportunities). Compare destination
retention on this fixed denominator, attribute known/unreferenced coverage and
constraint failures. This is not a replacement gate, new benchmark, or complete
enumeration of feasible route classes. Run the same analysis for all retained
controls, not just a favorable arm.

Final report includes all negative variants, restricted-population confound,
per-seed metrics and differences, cluster-by-layout intervals, actual budget,
source/checkpoint/RNG/replay provenance, and a clear publishability decision.
Do not spend remaining time on more arbitrary loss variants, LoRA or RFT.
