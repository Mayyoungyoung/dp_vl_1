# RLBench 运动观测渲染的配对性能审计

固定 TRAIN 父 `reach_target_281000`、proposal 0 的两次独立进程采集均成功，初始 RGB-D、当前状态、相机参数、已记录世界状态及语言完全一致。原始 55 步 `gripper_pose` 与 `gripper_open` 逐值相等，最大差为 0。临时关闭运动期间 RGB-D 采集后，完整 worker 耗时从 28.036 秒降至 10.532 秒，单次配对提速 2.662 倍。该结果仅验证一个父场景与提案，尚不能证明所有任务和随机布局都等价。

`get_demo` 部分提速 48.548 倍，而总 worker 仅提速 2.662 倍；初始化、严格恢复、图像核验和模拟器关闭仍有成本。两臂顺序为 on 后 off、每臂一次，尚无多次计时置信区间；页缓存和系统负载也可能影响部分挂钟差异。原始 pose/open 相等包含夹爪事件相等；此父没有开闭转换，下一轮必须覆盖含抓放事件的任务。

此候选只临时修改已经存在的 front camera 配置，作用域限制在 `Scene.get_demo`。初始及每次恢复时的 RGB-D 仍开启，pose/open 继续每步读取；未调用会删除 sensor 的 `_set_camera_properties()`，不改变控制、规划、原任务成功标准或自由前缀。异常路径恢复开关的单元测试也通过。本轮没有测试运动前缀阶段的提速。

实际源码为 `ed710c3fbd2ae865122e19d2198e2a2c09e5ebd5`，服务器 `runs/observation_demo_render_benchmark_v1`，三个 recorded jobs 均 exit 0，外层也 exit 0。每个原始 worker 按预声明在首条提交后受控 exit 3，由审计 harness 核验后正常退出；这不是采集失败。服务器三项开关测试通过。实际 orchestration shell 在启动前固化绝对 release 路径，其 SHA256 为 `5c2e16d73d397b47a1f112e0eba88e7c9ef63343c3aa1db014db4496d7658d78`。代码、日志、比较结果、原始轨迹/观测 hash 见 `observation_demo_render_benchmark_v1/`；完整二进制存于服务器并有本地忽略归档。共消耗两个额外实际提案，未混入正式训练语料。

push_button 首个坐标差异出现在索引 2，不仅是尾部六步终止差异；共同时间索引上的最大位置差 0.193291 米，最终位置差 0.000417 米。长度不同，不能用小终点差或相同事件转换索引替代完整轨迹等值。固定源码中，采集器设置 Python/NumPy 随机状态；PyRep 在直线规划失败后可转随机 IK 与带挂钟预算的 SBL/OMPL，调用链未显式固定其随机种子。尚未追踪该父实际规划分支，不能将不等价归因为 OMPL。Scene 步回调默认为空、collector 未注册图像回调、该任务没有覆写 observation decorator；只读检查未发现任务按图像做决策，但不代表已穷尽检查 simulator 插件内部行为。

这里使用原始共同时间索引，没有时间配准或改变等值标准；长度不同导致其并非完整序列距离。完整姿态的逐值判断仍失败，另存 quaternion 符号无关的角度差。on/on 控制说明此次跨进程采集本身已有轨迹不确定性，单次 on/off 差异不能据此归因于渲染开关，也不能反推开关完全无影响。六任务严格等值条件仍未满足，不能自动推广 off 采集。全部审计共额外 13 个实际提案，worker 实耗合计 384.615 秒；详情见 `observation_demo_render_push_on_control_v1/pairwise_diagnostics.json`。

正式六任务采集始终保持固定 6c 源及运动相机开启；本审计不修改、不停止该作业。即便六任务全部通过，也只能支持这些训练父上的性能候选，后续新批次需显式版本与执行参数，不能把历史默认采集静默替换。
