# One proposed diagnostic: fixed TRAIN8 teacher-forced coordinate audit

Status: implemented for source review; no diagnostic model forward or new training has run. Root approved only this fixed nine-forward diagnostic after source freeze and CPU checks. Its purpose is to distinguish an implementation/representation error, poor coordinate fitting, and an autoregressive rollout gap using existing evidence. It is not a new research mechanism or an automatic continuation request.

Use the same eight registered TRAIN parents272000–272007, target0, and the first recorded positive reference (index0) per instruction. Lock original observation/reference hashes against the completed SFT index. Keep the exact trained processor, serializer, horizon24, K1, checkpoint and model.eval behavior. No DEV, calibration or locked inputs are opened. Reference answers are used only for this explicitly teacher-forced diagnostic, never added to a generation prefix.

1. **CPU/interface stage:** inspect those eight original meter-coordinate references and their exact integer-mm serialization. Report per-axis ranges, coordinate/error histograms and round-trip maximum error (expected<=0.5mm per axis), along with actual prefix/answer token IDs. Confirm all prompt labels are-100 and every supervised label corresponds to the intended next token. Reproduce the trainer's t→t+1 shift using the actual processor sequence, not guessed prompt length. Stop if answer-token offset mapping does not exactly match the supervised token slice.
2. **One frozen-model pass per sample:** reuse the actual hidden-state/lm-head/chunked causal loss implementation, with no gradients or updates. Partition every supervised token exactly once into syntax-only, coordinate-only, event-only, mixed-character and termination categories. Use tokenizer character offsets over the exact compact answer; a token spanning punctuation and a numeric sign must be labeled mixed, not arbitrarily assigned to coordinates. Record category counts, NLL sums/means and top1 accuracy. Their sums must reconcile with the unchanged total token objective.
3. **Coordinate readout:** retain top1 token IDs and construct per-scalar teacher-forced integer predictions only when they form a valid complete integer; otherwise count that scalar as unparsable. Report signed-axis errors and endpoint-coordinate error separately from token accuracy. Concatenated top1 predictions receive the true preceding tokens at each position; call this a conditional readout, not an autoregressive trajectory or a success rate. Compare against the eight original frozen free-generation endpoints without making new rollout requests.
4. **One causal control:** for the first TRAIN sample only, alter the last pure coordinate token to the first different token in the fixed0–9 digit list in a copied input and re-run once. Compare all vocabulary logits at all positions before that input token, including the full prompt, in chunks64. The declared comparison is `abs(new-old) <= 1e-3 + 1e-4*abs(old)`. BF16 base/head outputs are converted to FP32 after the vocabulary projection; FP32 comparison does not recover BF16 precision. This small nonzero tolerance accommodates repeated CUDA arithmetic but does not exempt BF16-sized discrepancies; also record exact maximum difference, scaled difference and violation count. Record hidden-state change at/after the mutation as a control. This verifies this actual call's causal behavior; it does not replace source inspection or turn an answer-containing teacher-forced input into a generation condition.

Proposed compute ceiling: eight teacher-forced forwards plus one late-token control (nine total), no backward pass, no generation, no new optimizer state. GPU1/35%, CPU1, chunk-size64 as the actual SFT implementation. Allow at most60s reserved GPU wall time for the diagnostic body after startup; stop and record any implementation/memory failure without fallback or repeat. Expected cost is far below another120-request generation run, but remains unmeasured until root freezes and authorizes it. Save only token IDs, scalar errors, masks/offsets, small summaries and provenance; never full vocabulary logits or another foundation-model copy.

Implementation: `scripts/audit_vlm_sft_teacher_forcing.py` plus `routeset/vlm_teacher_audit.py`. It never calls the broad TRAIN/DEV data loader. Metadata identities and all eight reference-index0 hashes are checked before raw route access; only the fixed eight RGB/current/reference files are decoded. Byte-for-byte original training source guards remain strict. Original training helpers were CRLF on the server; any newly exported LF counterpart must not be silently accepted as identical. The first eight actual processor label/offset checks run before model loading. No extra warmup or generation calls are made. Failure/budget receipts and any completed sample records survive, with actual attempted forward count; CUDA work already submitted cannot be cancelled, so final synchronization and elapsed overshoot are explicitly recorded. No automatic resume/retry is offered for this bounded diagnostic.

Local validation: eight pure tests passed; the two small Torch checks require the existing server `.venv` and have not yet run for this new source. They test exact causal shift/loss reconciliation and detection of a non-top1 difference inside the complete compared prefix. They do not replace the real Qwen ninth-forward check. The unchanged source loss is recomputed from each same hidden state; per-token sums must agree within2e-6 absolute and relative tolerance. Syntax/mixed/coordinate/event/termination counts partition all supervised tokens, including chat termination. Mixed-token scalar readouts require surrounding characters in their original token spans to match exactly; no predicted-character truncation or scalar repair is allowed. Conditional endpoint errors are against the same first positive reference and are not the previously reported semantic-target metric.

Interpretation is conditional. A unit/mask/shift failure warrants a versioned implementation correction and fair retraining; none has been found yet. High coordinate NLL/top1 error despite low syntax/event loss supports underfitting of spatial outputs and motivates examining exposure/representation before any larger evaluation. Good conditional coordinate readout with poor saved free generations supports an autoregressive rollout gap, but does not prove a specific remedy. Insensitivity to future-token changes confirms only causality. No result here alone distinguishes insufficient exposure from unsuitable spatial input encoding; do not claim that without a later matched control.

The original3750 supervised route slots and3–8 exposures per selected instruction are far below the regression baseline's actual160000 slots to its selected checkpoint (384000 full run); this is an unresolved fairness limit. No claim that SFT as a method cannot work is justified. Low next-token loss can coexist with poor rollouts in correlated continuous sequences, as illustrated in the primary [FAST paper, Section IV](https://arxiv.org/html/2501.09747v1), but that high-frequency-control study does not establish the cause in this H24 task-level route setting.
