# Composite108 ordinary constant12000 control

This is a prospective data-size control using the existing ordinary model. It is not a new route-set mechanism. Implementation, actual data quality, successful Qwen encoding and completed training are separate claims. This protocol authorizes no automatic stage chaining; root separately launches each stage from an immutable release with record_job receipts, CPU1, and GPU1/35% only where required.

The only data selection is old64 TRAIN plus extension first32 TRAIN, and the unchanged old12 reused DEV. The composite exporter must already seal all108 requested parents with dual mechanical gates and registered exact/1mm cross-corpus checks. Missing inputs are retained in288 requested TRAIN inputs; old missing parent means at most285 observed TRAIN inputs before any new failure. New32 DEV remains sealed and is never encoded, loaded, used for selection or included in metrics.

`quality` is CPU-only. It revalidates the composite export and audits every actual TRAIN condition and every known positive, including unknown types and long paths. It uses the unchanged model `resample_event_segments` to H24, the existing two-row tip checks, stride2 observed RGB-D backprojection and the old coordinatewise±.05m endpoint-support test. No reference is deleted or shortened. Any endpoint-capacity failure blocks later stages. Export success is not capacity success. H24 geometry diagnostics are recorded, not used as an automatic filtering rule. Only TRAIN raw arrays are opened for quality; old source hashes may be verified without decoding their DEV arrays.

`cache` requires the complete passing quality receipt. Historical prefix76 cache metadata hashes and actual extractor source are pinned. All225 old NPZ files are verified against the original observation row, role, image SHA, token count, exact allowed fields, finite float32 2048+2048 hidden arrays and original NPZ SHA. The model revision/processor, transformers4.57.1, max-pixels262144, dtype and complete encoder configuration are checked. Their NPZ bytes are copied without re-encoding, so all36 reused DEV feature arrays and container bytes remain exactly unchanged. Only appended actual extension TRAIN rows (at most96) enter a new observation-only manifest and the original pinned Qwen cache program. Its config must match the actual old cache except manifest SHA. The merged index has the composite observation-manifest SHA and a distinct reuse receipt. Old extraction costs remain historical; new load/encoding, merge/validation costs are separately retained and never described as online inference latency. Cache stage is fresh-only: a failed partial encoding is preserved and is not automatically reissued.

`train` separately requires current composite mechanical gates, the quality receipt and complete cache provenance. It calls the unchanged `train_observed_geometry.train` with the original4096/H24/K4/128/2/point64 ordinary peak/surface architecture, saturation objective, grounding loss.02/σ.025, seed0, batch32, constant AdamW LR.0003 and weight decay1e-4. Only a scoped evaluation adapter redirects export verification to the dual-corpus verifier; the original two-row metric functions, post-pool label access, candidate denominator and selection rule remain unchanged. No no-direct removal, new attention, local refiner, schedule search or new core mechanism is included.

Training uses12000 steps,384000 observation draws,1536000 candidate path states and48 DEV opportunities at every250 steps. Initialization is checked before the first optimization batch against the original model tensor digest, Torch RNG and sampler initial state. Batch index chains are recorded, but the larger sampling population means the actual chain is not required to equal the old data run. All actual observations remain in TRAIN evaluation; the unchanged loop optimizes only conditions having at least one known positive, and records unreferenced inputs. The last and best pools are saved with their original criteria. The original latency diagnostic adds24 head requests/96 path states and excludes Qwen/checking; it is not an end-to-end result.

This comparison matches total training budget, model and initialization, not each parent/input's exposure. Resume requires the original output's actual last checkpoint plus unchanged policy, source hashes, data, quality and cache receipt. The shared loop restores optimizer, constant scheduler, RNG, sampler, step, exposure and history. Requested stops can occur only at predeclared250-step evaluation positions, so no extra model-selection opportunities are introduced. The driver has an exclusive lock in addition to the original loop lock. A completed12000 checkpoint may be resumed only with a matching sealed summary and all prediction pools; otherwise it fails closed rather than replaying final inference. Each process attempt's wall time is appended separately; lost work since a checkpoint is not included in the loop's checkpoint cost and must be accounted using these process receipts.

`fixed-last-train` is a separate CPU-only diagnostic after completed training. It generates once for every actual TRAIN input, including those without references, using only the frozen last12000 checkpoint. It reports the actual request count and4×path states, zero Qwen/DEV/optimization. A complete sealed diagnostic can be reused without forward; an incomplete one is kept with its full request upper bound and is not automatically replayed.

The independent entry is `python -m scripts.run_observed_two_row_composite --stage quality|cache|train|fixed-last-train --data <composite_export> --policy configs/observed_two_row_composite108_training_v1.json --output <fresh_stage_output>`. Cache/train/diagnostic additionally require `--quality-audit`; cache requires `--model <pinned Qwen directory>`; the diagnostic requires `--model-folder <completed training>`. Only training accepts `--resume` and a predeclared `--stop-after`. Root supplies frozen record_job wrappers after review; no implementation-time command starts a server job.
